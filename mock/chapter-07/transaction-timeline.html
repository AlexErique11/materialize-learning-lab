Transaction timeline

A later read can preserve ordering by waiting—or trade freshness for a snapshot.

A strict-serializable transaction orders reads inside Materialize. It does not by itself guarantee that a write in an upstream database has already been ingested.

Illustrative model: transaction A reads a base row at time 8 and commits; transaction B then queries a derived view that includes the row only after its frontier advances beyond 8. Bounded staleness never waits for that progress and errors if no sufficiently fresh shared time is available.
